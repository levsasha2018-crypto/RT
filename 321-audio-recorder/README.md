# Аудиорекордер, задания 3.2.1–3.2.7д

Основа — собственный `311-adc`, общие библиотеки из `../libs`.
Материалы курса обновлены 5 ноября 2026 года: es-book `44854d6`, es-test `fac5b2b`.

## Подключения

Для испытательного сигнала: GP20 (физический контакт 26) → GP26 (31).
RC-цепь занятия 3.1 снимается целиком.

Для голоса перемычка GP20–GP26 обязательно снимается. MAX9814:

| MAX9814 | Pico |
| --- | --- |
| Vdd | 3V3(OUT), контакт 36 |
| GND | GND, контакт 38 |
| Out | GP26, контакт 31 |
| Gain | Vdd самого модуля |
| AR | свободен |

Менять подключения при отключённом USB. Кнопки GP15–GND и GP14–GND могут
оставаться; используется GP15. Встроенный LED — GP25.

## Устройство

- `platform`: АЦП с делителем на 44100 Гц, таймерные IRQ, три канала DMA,
  ШИМ GP20 и watchdog. Буферы занимают 30432 байта, лимит 32 КиБ проверяется
  `_Static_assert` при сборке. Остановка DMA разрывает цепочку до abort (RP2040-E13).
- `logic/block-task`: неблокирующий захват до 8192 отсчётов, результат через callback.
- `logic/stream-task`: два буфера по 1024 байта, заголовок 6 байт,
  счётчики кадров, отсчётов и переполнений. 512 отсчётов при 16 битах,
  1024 при 8 битах. Сдвиг делает АЦП, передача DMA_SIZE_8.
- `api-callbacks.c`: команды и расчёт статистики, двоичная отправка без CRLF.
- `main.c`: восемь секундомеров, watchdog обновляется после всех задач.
- `rec_audio.py`: официальный скрипт курса, настройка UTF-8 для Windows;
  комментарии с текстом песни заменены номерами музыкальных фраз.

SDK недоступен логике; старые проекты не изменены.

## Проверка на Pico 5 ноября

Плата `E66098F29B4B8932`, COM14. Сборка GCC 15.2.1 / Pico SDK 2.3.0,
Release, `-Wall`, без предупреждений; `.bin` 47396 байт.

| Задание | Настоящий результат | Локальная проверка без повторной сборки |
| --- | --- | --- |
| 3.2.1 | 24 переключения за 6 с при 250 мс; 20 за 2 с при 100 мс | 22/22 |
| 3.2.2 | 125 мкс: интервалы 123–125 мкс; 23 мкс: 5–41 мкс, обработчик 8.8 % | 21/21 |
| 3.2.3 | 4410 отсчётов: 99998 мкс; 8192: 185760 мкс | 28/28 |
| 3.2.4 | 432 кадра / 221184 отсчёта за 5 с; пропусков и переполнений 0 | 27/27 |
| 3.2.5 | 25.30 с, 2179 кадров, 43 ноты; все частоты в допуске 1 % | 18/18 |
| 3.2.6 | прибор живёт дольше таймаута; после hang — reset: watchdog, restarts 1 | 22/22 |
| 3.2.7, 3.2.7д | прошивка и скрипты готовы; запись с MAX9814 следующим шагом | ожидает записи |

Для рабочего рекордера предварительно выбран watchdog **100 мс**: это больше
времени отправки кадра с запасом и ограничивает зависание примерно девятью
буферами. Окончательное значение сверяется с максимальным временем суперцикла
при реальном потоке. Watchdog не включается автоматически: команда
`wdt_enable 100` включает его явно. Для демонстрации используется 2000 мс.

## Повторение записи

```powershell
python -m pip install pyserial
python check-3-2-1.py
python check-3-2-2.py
python check-3-2-3.py
python rec_audio.py --seconds 5
# Только с перемычкой GP20–GP26:
python rec_audio.py --wav melody.wav --melody
python check-3-2-6.py
# После замены перемычки подключённым MAX9814:
python check-3-2-7.py
python rec_audio.py --seconds 3 --wav recording.wav
python rec_audio.py --seconds 3 --wav recording-8bit.wav --bits 8
```

Последние две записи выполняются, когда человек говорит в микрофон.
Все аппаратные файлы создаются настоящим обменом с Pico.
