# Прогон на Pico и отправка результатов

## Подключение

Нужны обычная Raspberry Pi Pico (RP2040), USB-кабель с передачей данных,
макетная плата, кнопка и соединительные провода. Подключите кнопку между **GP15** и **GND**.
Вход использует внутреннюю подтяжку вверх: отпущенная кнопка даёт 1, нажатая — 0.
Светодиод уже находится на плате, GP25. У четырёхконтактной кнопки выбирайте контакты,
которые замыкаются при нажатии, а не два постоянно соединённых вывода.

## Запись прошивки

1. Соберите нужный проект.
2. Отключите USB, зажмите BOOTSEL и подключите USB снова.
3. Отпустите BOOTSEL, когда появился накопитель `RPI-RP2`.
4. Скопируйте `.uf2` соответствующего проекта из его папки `build` на этот накопитель.
5. Pico перезапустится. Для проектов 1.3 появится последовательный порт USB CDC.

Перепрошивка заменяет работающую программу, поэтому выполняйте проекты по порядку.
Не запускайте терминал последовательного порта и проверяющий Python-скрипт одновременно.

## Порядок проверки

| Прошивка | Что сделать |
| --- | --- |
| `112_blink.uf2` | Убедиться: светодиод горит 250 мс, погашен 1000 мс |
| `121_blink_reg.uf2` | Убедиться в таком же мигании при работе через регистры |
| `122_led_button.uf2` | Проверить переключение по нажатию; возможен дребезг |
| `123_led_button_debounce.uf2` | Десять нажатий с полным отпусканием — десять переключений |
| `131_hello_usb.uf2` | Запустить `python 131-hello-usb/check-1-3-2.py` (10 секунд) |
| `133_led_button_usb.uf2` | Запустить `python 133-led-button-usb/check-1-3-3.py`, нажать кнопку шесть раз с интервалами больше 0,2 с |
| Та же прошивка | Запустить `python 133-led-button-usb/check-1-3-4.py`; скрипт отправит команды автоматически |
| `134_led_module.uf2` | Запустить `python 134-led-module/check-1-3-6.py`, затем `python 134-led-module/check-1-3-7.py` |

Дополнительно `python 131-hello-usb/check-1-3-1.py` сохраняет лог с номером 1.3.1.
Для этой проверки GitHub проверяет исходники и сборку; основной лог Hello World нужен в 1.3.2.

Скрипты ищут USB-устройство `2e8a:000a` и сохраняют логи рядом с собой,
независимо от текущей папки терминала. Если плата не найдена, скрипт завершится с ошибкой.
Серийный номер берётся из USB-дескриптора, а в задании 1.3.7 сверяется с ответом прошивки.

В проекте 1.3.4 проверьте вручную совместную работу кнопки и USB.
Если оба события обработаны в одном цикле, состояние после команды USB имеет приоритет.

Для 1.3.6 сравните `build` и `build-log2`: во второй сборке сообщения `dbg` отключены,
команды `v` и `i` доступны при любом уровне. После сравнения верните прошивку из `build`
с уровнем 3 и снимите окончательный лог.

## Сдача

После настоящего прогона:

```powershell
git add 131-hello-usb/device-1-3-2.log
git add 133-led-button-usb/device-1-3-3.log 133-led-button-usb/device-1-3-4.log
git add 134-led-module/device-1-3-6.log 134-led-module/device-1-3-7.log
git commit -m "Record Pico hardware checks for lessons 1.1-1.3"
git push
```

Откройте [GitHub Actions](https://github.com/levsasha2018-crypto/RT/actions).
В каждом запуске посмотрите пункты проверки и шаг отправки результата на платформу.
Успешная отправка должна получить ответ HTTP 200.
Проверка без `ES_ACCOUNT_SECRET` показывает результат только в GitHub.
Сам секрет не добавляют в исходники, README, логи или коммиты.
